# M331：优化 A53 与稳定 PL 的同会话成对单链对照

日期：2026-09-26。状态：**C 阶段 PASS（限冻结 M128 的两个代表性单链形状）**；不是整模型 CPU-only 或视频加速比。

沿用 M329 已通过的七个 CPU 数值 case 和稳定 PL 两个 case，不重复其数值门禁。M330 增加优化 A53 原生 C++ 的完整 FP16 数值与预解包成本；本轮仅补新的、公平顺序的性能对照。COM3 同一授权终端先执行 root/XRT/PYNQ/19 文件及包清单 SHA-256 预检，加载既有稳定 Build `0x4D395832`；未生成或晋级新 bitstream。稳定服务 8001 不在运行，FPGA 无其他 owner。板端独立候选目录，不改稳定回滚/boot/DTB/CMA/分区。

CPU 路径单线程绑核 1，`g++ 11.4.0 -O3 -std=c++17 -ffp-contract=off -fno-fast-math -march=armv8-a+simd`。CPU 每次从内存中的原始打包 fixture 计算完整输出，计时不含进程启动、fixture 文件读取/解析和结果文件写盘。PL 每次由内存中的 packet/权重开始，计入权重及输入 CMA staging/sync、寄存器、DMA 启动至完成等待、输出 sync/copy；不含一次性 overlay 加载 `2034.576 ms` 或 buffer 分配。两个实现不是相同 API，但量化数值、形状和冻结 fixture 一致；CPU 对原始 FP16、PL 对既定 FP16-FTZ 契约分别校验完整输出。

每个形状 10 对，偶数序号 CPU→PL，奇数序号 PL→CPU；没有丢弃首对或挑选最快值。原始逐对数值、顺序、阶段时间和 DMA 快照在 `BOARD_RESULT.json`：

| 双 descriptor case | CPU 原始打包计算中位数/范围 | PL 完整事务中位数/范围 | 逐对 CPU/PL 比值中位数/范围 |
|---|---:|---:|---:|
| W2，layer0/family4，40 groups | 5.891 ms / 5.878–5.903 | 2.244 ms / 2.090–2.423 | 2.625× / 2.432–2.819 |
| W4，layer0/family5，40 groups | 5.871 ms / 5.864–5.986 | 2.525 ms / 2.493–2.685 | 2.328× / 2.190–2.369 |

执行顺序分组后，W2 的 PL 中位数 CPU→PL/PL→CPU 为 `2.237/2.251 ms`，W4 为 `2.526/2.523 ms`；本小样本内未见显著顺序倒置。20 对 CPU 完整原始 FP16 输出精确，PL 完整 FP16-FTZ 输出精确，所有 PL 返回 `0x4D395832`、DMA idle 且无错误；失败/超时 0。PL 等待阶段不能等同于纯核计算。

关于 M330 的预解包：这两个形状的预解包后算术约 `4.50 ms`，但每次还需约 `1.52 ms` 预处理和 `174,080 B` 额外表；只运行一次时并不优于原始打包 CPU 路径。没有证明全模型常驻预解包可行；必须单独核算权重占用、生命周期与边缘板可用内存。M329 旧 Python/NumPy `449/498 ms` 不参与本轮速度比计算。

结果含义：对于这两个代表性冻结 Linear 单链，稳定 PL 的含 staging 事务仍比优化后 A53 的原始打包计算更快；这支持保留 PS–PL 划分，但**不证明** 4B 整模型优于 CPU、视频首 Token 缩短、吞吐改善或低功率优势。M328 固定视频 `230.721 s` 基线不变。若下一步优化端到端，必须首先在完整视频上证明收益。

证据：原始 COM3 `tmp/m331/board_paired_01.log`、`board_result_hashes_01.log`、`paired_base64_uart.log`；板端机器结果原 SHA-256 `3e1409ca5ac1999d977613e4d3cbe01812f85e1c12cf10f517bff324aca2bb63`，本地逐字节导回 `BOARD_RESULT.json`，复算 `SUMMARY.json`。M330 的源、runner、数值与预解包结果见上一轮报告。下一步 D：先根据历史 B 的 43.638 s 视觉与 187.011 s 后续语言大项，选单一低风险候选并预登记端到端门槛；不可从单链 2.x 倍直接推算视频收益。
