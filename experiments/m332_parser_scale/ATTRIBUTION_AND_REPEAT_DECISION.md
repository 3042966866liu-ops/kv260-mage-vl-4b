首 Token 差额几乎全部落在语言 Prefill 段；视觉塔与预处理没有变慢。加载前段差了 44.060 s，但它不在首 Token 的计时区间内，不能拿它直接解释 20.224 s。两次输入张量 SHA-256 都是 `5911485955780036ac4c8990bcaa248667f2e86bd1fd6f9b0783002553b4adff`，159 Token、Build `0x4D395832`、778 次逻辑 FPGA 调用及最终 Token/分数相同。候选模块实际路径和 SHA 与冻结 M332 源一致；未发现错误调用旧模块或重新改变输入规模的证据。

当前 M277 视频记录只把语言阶段作为一个整体，**没有**同轮权重读取、解析、PS 算子、DMA/设备等待的子阶段计数。因而不能声称“解析器造成 20 秒回退”，也不能把全部 20 秒称作纯 PL 时间。历史 M239 对**不同的 849-Token/4,184 物理调用**输入记录过 `parse=181.189 s`、`launch_wait=562.050 s`，且与总墙钟可能重叠；它只说明这些子阶段值得在后续 159-Token 真路径分别计时，不能作为本轮 778 调用的归因或节省量。

## 是否满足补测条件

相同帧张量 SHA 和 M277 包清单 SHA `0e1bdfa578f655b2bb6d07b097f1dda115a7936906e3e112137123db65e7f2fa` 的两次历史稳定运行，首 Token 为 230.263 s 与 213.634 s，差 16.628 s；另一个 M328 独立安装运行是 230.721 s。它们不是本轮严格同会话配对，不能据此估计本轮置信区间；但同负载语言阶段有十余秒量级的已观察波动。本轮稳定样本 205.050 s 比上述三次都快，存在顺序/缓存/温度等运行条件掩盖候选小幅收益的合理疑点，**尚无具体原因证据**。

因此只允许再做**一组**反向顺序 `candidate → baseline`，使用相同四帧、包/模块哈希、Build 和计时边界。先冻结判定：两组都需功能一致；若复测仍不见至少 11.536 s 的候选收益，关闭 M332；即便复测出现收益，只要原组仍为负，不能把候选说成已稳健提速或替换稳定部署。不得扩展成无上限重测。其后转向对 159-Token 真路径的权重读取、解析、设备等待与 PS 分段画像，优先处理实测主项。

证据：本目录 `BASELINE_BOARD_RESULT.json`、`CANDIDATE_BOARD_RESULT.json`、`SUMMARY.json`，原始 COM3 记录 `tmp/m332/video_baseline_uart.log`、`tmp/m332/video_v2_candidate_uart.log`；历史 `deployment/mage_vl4b/M277_M276_FIXED_WINDOW_BOARD_RESULT_01.json`、`..._04.json` 和 `deployment/mage_vl4b/M328_RELEASE_VIDEO_BOARD_RESULT.json`。稳定部署及回滚均保持原样。
