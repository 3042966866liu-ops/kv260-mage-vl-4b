# Local release readiness — 2026-09-26 (post-install update)

The source-and-documentation snapshot was pushed to the [GitHub repository](https://github.com/3042966866liu-ops/kv260-mage-vl-4b) on `main` at initial release commit `69b14e8ac616b1c5c50f67d73c52190e961c9ea7`. This document describes the owner's local installation and evidence status; it is not a claim that prebuilt assets are publicly available or that a GitHub Release exists. The conservative default is M254/M120/T32 Build `0x4D395832`. OP01 Decode-one remains experimental.

## What is already evidenced

- M0–M4 source staging, path whitelist, recursive dependency check, JSON/Python/Bash syntax, frozen BACT selector/cost/quality replay, and local per-file package hashes passed. See `manifests/release_files.json` and `INSTALL_PACKAGE_MANIFEST.json` in the generated install directory.
- The owner's local prebuilt archive contains the exact M125 language/LM Head shards, stable bit/hwh, vision, tokenizer, detector, and auxiliary assets. These large files are deliberately outside the Git source tree. The local archive has **no public download URL**.
- A separate v4 install on the owner's KV260 verified all 450 files, then passed the environment, Build-ID-only and fixed-text FPGA E2E gates. Build-ID was `0x4D395832`, generated Token `17` matched the fixed reference, logical/physical FPGA calls were `162/165`, and CPU Linear fallback was false. Fixed-text total was `62.468 s`; this is not video TTFT or sustained throughput. The historical descriptor/chain/layer gates were reused only at exact stable bit/hwh identity, not freshly rerun in the new directory.
- The first v4 Web service start failed **before** overlay/model load because the launcher omitted the M175 `runtime` module search path (`board_runtime` import). The corrected v5 launcher passed a release-root module-path probe and its independent installation passed 450-file hashes, Build-ID-only and fixed-text E2E (Token `17`, 162 logical/165 physical FPGA calls, `61.901 s`). Its idle HTTP/Build-ID check passed, but `live/start` then failed on missing `torch` in the isolated runtime. No video inference occurred. The v5 service stopped itself; the stable installation was untouched.
- v6 added a hash-locked 36-wheel ARM64 bundle and an isolated installer with native Torch/torchvision smoke. The wheel archive is a local asset, not a published download.
- Subsequent v6 testing proved 452 installed-file hashes, isolated Torch/torchvision native-op smoke, Build-ID-only and the same fixed-text E2E (Token `17`, 162 logical/165 physical calls, `62.802 s`). Its Web worker then failed because the PYNQ system Pillow 9.0.1 lacks `Image.Resampling`, which is required by bundled Transformers 5.7.0. The hash-locked historical M193 Pillow 12.1.0 wheel was therefore added to v7 rather than reusing the system package.
- The immutable **v7** TAR `kv260-mage-vl-4b-prebuilt-install-20260926-v7.tar` (SHA-256 `c487e16bcc18698808d7c48822e355c8b6cf291633b00d661f372f7280d41145`) passed a separate KV260 first install: 453 file hashes; 37 isolated wheels including Pillow 12.1.0 and native NMS; stable Build-ID `0x4D395832`; fixed-text Token `17`, 162 logical/165 physical FPGA calls, no CPU Linear fallback, `62.083 s`. A localhost-only Web smoke then returned HTTP 202 and reached runtime-ready with the expected M238/M241 classes and release-root module paths. **No video frame was submitted**. See the parent workspace `deployment/mage_vl4b/M327_RELEASE_FIRST_INSTALL_V7_RESULT.json`. This file is a post-install source-tree update; the immutable v7 TAR contains its earlier, preverification copy of this readiness document.
- A later, separately hash-locked M328 v3 companion submitted the original four RGB448 frames through the frozen M277 direct 4B entry in that independent v7 install. The board verified all five companion files, the ordered tensor and the release M277 runtime-source subset; 24 vision layers, 159-token T32 language Prefill and 778 logical FPGA calls completed on Build `0x4D395832` with no language CPU Linear fallback. Output `0`/token `15`/`ABSENT` matched the fixed reference. First Token was `230.721 s` excluding model/runtime load; the complete validation runner took `511.854 s`. This is a fixed-video E2E PASS for the **direct** 4B entry only, not a Web alarm-triggered review. See parent `deployment/mage_vl4b/M328_RELEASE_VIDEO_BOARD_RESULT.json` and [fixed-video reproduction](docs/fixed_video_reproduction.md). ## Current scope and unresolved items

| Capability | Current conclusion |
| --- | --- |
| `SOURCE_REVIEWABLE` | Yes locally, subject to upstream attribution and owner license decision. |
| `OFFLINE_REPRODUCED` | Yes for frozen M321 BACT evidence only; not a new model-quality result. |
| `PREBUILT_READY` | **Yes locally for exact KV260 fixed-text E2E, Web runtime startup and separate-companion direct fixed-video E2E.** Alarm-triggered Web 4B video, sustained throughput and clean generic OS provisioning remain unverified. Neither TAR has a public download URL. |
| `SOURCE_BUILD_VERIFIED` | Not run. No clean Vivado full-shell rebuild claim. |

The source snapshot is online, but a broadly reusable software/asset release remains blocked by the owner's source-license choice, file-level attribution/redistribution review, and a lawful distribution method for the large hash-locked assets and companion. An unuploaded address must not be invented. This local first-install check does not prove a generic clean OS image can satisfy the observed PYNQ/XRT/Torch environment without additional provisioning. M328 supplies the previously missing fixed-window direct-video gate; the earlier fixed-text and no-frame Web service checks remain distinct and must not be described as an alarm-triggered video Web gate. M328 uses only the last submitted frame for two visual views, so it does not establish four-frame temporal reasoning or real-time operation. The remaining experiments and their acceptance boundaries are in [next validation gates](docs/next_validation.md).
