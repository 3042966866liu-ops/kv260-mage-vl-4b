# 当前展示入口：上传视频，发现刀具时报警

启动命令见 `README.md`，地址仍为 http://127.0.0.1:8765 。当前根页面为 `static/demo.html`，旧仪表盘入口不再对外提供。

## 用户已确定的行为

- 上传本地 MP4/WebM，最大100 MiB，浏览器实际解码后抽取1–3张448×448 RGB画面。
- 上传/采样准备结束后播放视频，由真实`play`事件自动提交串行识别任务；无需再点“开始识别”。暂停/继续播放不会重复提交，已完成的视频重播也不会静默重跑模型。
- 当前上传视频的真实板端结果为 **Yes** 时显示巨大红色三角警示及“警惕！检测到刀具”。
- **No** 时不弹窗、不响铃、不显示红色警示，也不显示“无刀具”等结果文字，视频正常播放。
- 等待、失联或输出不明确，不当作No，也不显示伪造的刀具报警。
- 网页不展示TTFT、耗时、性能图表。这些数据仅保存在后台证据中。
- 遇到Yes立即显示警示，不再等待剩余采样；全为No也只能表述采样范围，不声称检查了每一帧。

## 当前真实状态

上传、视频播放、浏览器真实采样、RGB/NPY保存、播放触发串行队列及结果证据校验均已实现。**板端持久工作器尚未接通；新上传帧通道也尚未完成上板验收**。未连接时可正常播放，但不能产生识别任务；状态明确显示等待连接。不会通过文件名或预置标签产生识别答案。

已收到四段校园素材，并按用户要求保留旧实验室视频，来源及可见性记录见`EVALUATION_DATASET_M530_CAMPUS_DEMO_V1.json`和M530媒体复核报告。它们仍需独立模型/板端验收，不能继承旧两段视频四窗口4/4结果。原模型、学习头和硬件回滚保持。

当前是预先提取有限采样帧、播放触发计算，不是逐帧实时检测。报警时间取决于真实结果返回；不能按预设秒数报警。上传、采样和预热属于播放前准备，分别保留后台记录。旧热态约29秒不能直接转为新素材延迟保证；30秒视频偏紧，45～60秒更适合预留演示余量，但不保证在结束前完成。素材尽量让刀具较早出现并持续清晰可见。

## 两问题实验

`RELATIONAL_EXPERIMENT.json` 将“刀在桌上”“手里持刀”“手持金属尺”三类画面和两个问题分开定义。6条教师判断、6条无头学生、6条现有补偿学生为有界软件对照草案；先等真实素材并冻结实际文本/token IDs。**“是否有人手持刀具”目前保持禁用**，接口也拒绝把旧问题结果冒充新任务。
