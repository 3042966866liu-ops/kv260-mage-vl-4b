## 对应固定视频的互斥顶层时间

稳定 Build `0x4D395832`，独立 v7 安装的 M277/M276 直接入口，原四张 RGB448 帧按顺序提交，但实际仅末帧 `[3]` 形成两个视图；159 总 Token/98 视觉 Token/5 个 T32 批/778 次语言逻辑调用。Token `15`、文本 `0`、无语言 CPU Linear fallback。下表为**单次** M328 请求，不是分布统计。

| 互斥阶段 | 实测 ms | 占不含加载的首 Token | 边界 |
|---|---:|---:|---|
| 视频预处理 | 71.982 | 0.031% | 取末帧、生成视觉输入；不含浏览器上传 |
| PS 视觉塔 | 43,637.717 | 18.914% | 完整 24 层视觉前向 |
| Token 构建＋语言 Prefill＋受限 0/1 首 Token | 187,011.166 | 81.055% | 含 PS 运算、权重 staging、PL 事务、LM Head 和选择；当前结果未拆开 |
| 舍入/事件边界差 | 0.051 | <0.001% | 由已报告顶层数值相减；不是独立计时项 |
| **首 Token（加载外）** | **230,720.917** | **100%** | 不包含初始化 |

初始化至预处理 `149,694.920 ms` 单列，旧证据未将 overlay、模型/权重验证、缓冲区分配进一步拆开。完整 runner `511,853.873 ms` 包含更多校验、输出/收尾；不能把它当作纯首 Token 或用上述三项直接解释整个 runner。

**本样例两大互斥瓶颈：语言 Prefill 至首 Token约187.0秒、PS视觉塔约43.6秒。** 预处理仅约0.072秒。即使视觉时间理想地全消除，首 Token 下界仍约187.1秒；若只消除全部语言段，下界仍约43.7秒。这是算术上界，不是可实现加速预测。

## 细项证据的适用范围

M239 的真实 KV260 **849-token 语言-only**画像（`deployment/mage_vl4b/M239_FULL849_PROFILE_BOARD_RESULT_02.json`，SHA-256 `7a4aaa9c2da2a9f40b8f74b9e2a7db85b3a05c831ced151ad3fa4232e97ce456`）记录 Prefill `709,754.522 ms`，其中按互斥语言层 family 包围计时 `588,906.748 ms`、PS Attention/Norm/激活/Head 等残余 `120,847.774 ms`。它还记录 pack、输入复制/同步、寄存器设置、`launch_wait`、输出同步和 parse 等细项。由于 M238 预打包和 M236 输出解析并行，这些嵌套活动时间**不能相加**；`launch_wait` 也不等于纯 PL 计算。更关键的是：**849 Token 与 M328 的159 Token不同，不能把 M239 各细项按比例缩放成230.721秒的拆解。**

M294R3 的同板 159-token 历史三次语言探针为 `131,528.709/131,524.038/131,375.591 ms`（中位 `131,524.038 ms`；`deployment/mage_vl4b/M294R3_COUNTERBALANCED_BOUNDARY_BOARD_RESULT_05.json` SHA-256 `1a8138f92fc9340b1e5c660f886729cd725280d29877863af54cdd12aef895d1`）。它是复用视觉特征的边界扫描，不是 M328 固定视频完整请求，也未证明完全热缓存；不能与 M328 的 `187,011.166 ms` 拼成加速或退化结论。

尚未在**同一个 M328 请求**中拆出的项目：overlay/模型/缓冲分配，Token 构建与 LM Head，PS Norm/RoPE/Attention/激活，文件读取/解包/转换/复制/同步，描述符/寄存器，DMA 启动/等待内部，输出同步/解析，频率/温度/磁盘活动，以及开关计时开销。对这些项目均记 `NOT_RUN`，不是零耗时。只有继续做同输入细分测量才可得出更深瓶颈归因；本轮按用户决定不重测。阶段 C 的优化 CPU/PL 对照先行，不使用 M329 的 Python/NumPy 比值宣传硬件加速。
