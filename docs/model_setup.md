# Model and external assets

The board results identify `microsoft/Mage-VL` (4B deployment path). The exact upstream revision, download entitlement and model redistribution terms are **not established** by the copied package manifests. Do not substitute the current upstream latest revision and assume bitwise compatibility.

The stable language runtime expects W2/W4 four-port packed weights plus FP16 scales, T32 descriptors, an FP16 row-major embedding, tokenizer JSON, text norms, and a W4 PS vision payload. `m181_m120_video_board_candidate` contains small manifests/config/source but excludes its multi-hundred-MB binaries. The `weights_root` configuration must contain `language_fourport/` and `lmhead_fourport/`, each with `SIXPORT_LAYOUT_MANIFEST.json` and its referenced binary shards. The model also needs `m181.../vision_layout/weights*.bin`, `ps_vision_payload/vision_bf16.safetensors`, `text_auxiliary/embedding.fp16.rowmajor.bin`, tokenizer files, `text_norms.fp16.npz`, and raw-vision auxiliary bytes. The fast channel separately requires the SSDLite checkpoint.

The [external asset manifest](../manifests/external_assets.json) records known sizes/hashes and exact destination paths. A bounded [stable-asset provenance audit](stable_asset_provenance.md) located both exact M125 language and LM Head layouts in the owner's WSL artifact tree and rehashed their manifests, eight shards, and frozen M120 source checkpoint. Nearby M89Y/M89Z files are genuinely different layouts or payloads and were not substituted. The matching assets are **not bundled in this Git directory**. The owner reports an eight-part prebuilt TAR uploaded to [GitHub Releases](https://github.com/3042966866liu-ops/kv260-mage-vl-4b/releases), but its old two-part Release manifest must be replaced and the public copies rehashed before this is a verified download path; public availability also does not establish redistribution rights. `scripts/verify_prebuilt_package.py` checks every extracted file against the package manifest; `scripts/preflight.py --check` checks the runtime-critical identities and predecessor hashes. The historical runtime performs further contract checks. We did not reconstruct a complete raw-upstream-to-packed-weight conversion pipeline in this source snapshot. A fresh user needs the exact verified prebuilt TAR or lawful equivalent assets for first installation.

Do not edit historical `PACKAGE_MANIFEST.json` to make a new package appear hash-compatible. Keep a separately versioned release installation record once exact assets have been lawfully provisioned.
