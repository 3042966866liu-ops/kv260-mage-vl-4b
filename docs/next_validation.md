# 下一轮验证门槛（单链对照已完成，整模型与应用仍待验证）

本页把研究预览的三个主要缺口改为可判定的实验。它不是通过报告，也不改变稳定 M254/M120/T32 Build `0x4D395832`。现有实板事实见[结果](results.md)，代码入口见[源码导览](source_map.md)。

## 1. 从单链贡献推进到完整视频收益

M331 已对两个冻结 W2/W4 单链形状完成各 10 对同板交错优化 A53 CPU／稳定 PL 对照，完整输出及 DMA 状态通过；范围和计时边界见[CPU／PL 对照](cpu_pl_benchmark.md)。这解决了代表性单链问题，仍不能证明完整模型或视频收益。下一步固定视频、视图、Prompt、权重和量化，先对历史首 Token 的主要耗时项选择一个工程优化候选，保持模型数学与 Token 不变，测端到端前后变化。整模型 CPU-only 对照须先审计内存和算子覆盖；做不到则明确标 `NOT_RUN`。

通过条件：完整固定视频在相同输入和计时边界下数值不退步、重复测量达到预先声明的端到端改善门槛；未通过不能晋级稳定版。若板端内存或依赖使 PS-only 全模型无法运行，应明确写为 `NOT_RUN`；单 Linear 的收益不得冒充整模型加速。不能把不同模型的 Qwen 3B 或 WSL CPU 数字当作本模型的同条件基线。

## 2. 验证 BACT 的质量—成本优势

当前[配对记录](../experiments/bact_v2_quality/paired_quality.json)仅对已见过的 12 段 AI 视频复算；`bact-159` 与 `count-144` 都是 5 个 T32 批、结构性 778 次语言逻辑调用，历史 test 的综合 Q 同为约 `0.616667`。它们的文本组成不同，不能把任何质量差异直接归因于“多保留 15 Token”。九候选代理还是冻结 fixture，不是已经验证的逐视频自适应选择器。

下一实验须先冻结配置、阈值规则和指标，再采集来源独立、人工盲标的新视频；按源视频分 calibration/test，禁止旧 12 段进入新的独立 test。报告逐样本预测、刀具召回与误报、动作 Macro-F1、失败/拒答、实际 Token、批次数、调用数和板端墙钟。若要宣称“输入自适应”，选择器还必须读取真实视觉特征并展示不同视频产生不同预算；无删除 Token 的新接口须先与原接口输出一致。

通过条件：新 test 上在**相同硬件成本**下有预先定义的任务质量优势，或在**相同任务质量**下有实测成本优势。若无优势，只保留“固定 T32 批边界成本现象及负结果”，不将 fixture 选择写成已证实的泛化算法。

## 3. 把直接视频样例与 Web 闭环、时序能力分开

M328 已在独立安装目录完成固定样例的**直接** 4B 推理：首 Token `230.721 s`，778 次逻辑 FPGA 调用；原四帧输入仅由末帧构成两张视觉视图。因此仍有两个不同门禁：

1. Web 门禁：使用发布版入口提交带帧号和时间戳的真实画面，记录快速通道报警、任务入队、4B 复核触发、Build ID/FPGA 调用、SSE 回传与最终结果。快通道独自完成不算 4B Web E2E；保留服务恢复证据。
2. 时序门禁：先核对最终送入模型的多时刻画面和位置/遮罩，再做不删 Token 的接口等价检查；用首末位置、帧序倒置等固定问题证明回答确实受时间顺序影响。只有末帧视图的旧路径不能称为跨帧理解。

这两项均不得自动宣称秒级实时性。当前慢通道为分钟级；快通道可以持续接收，但安全/动作准确率仍需目标场景独立验证。

## 4. 可复现资产与授权

源码已上传 GitHub，但 v7 预构建 TAR、M328 视频伴随包、权重、bitstream 和 wheel 没有公开下载地址。要宣称“他人可复现完整板端推理”，需先完成文件级来源/再分发权审查、项目自有代码授权选择、合法资产分发及 SHA-256 清单，然后从独立目录按文档安装并复测。未清权或未上传时维持“源码与离线 BACT 证据可复现；完整板端安装仅所有者本地验证”的表述。

优先顺序：完整固定视频工程收益 → 新数据上的 BACT 质量门禁 → Web 触发闭环与真正多时刻输入 → 资产/授权公开分发。任何一项失败都记录原始结果，不通过改文案、换样本或放宽门槛改写为 PASS。
