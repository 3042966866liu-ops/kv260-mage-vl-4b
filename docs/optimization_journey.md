# 从模型适配到实际等待时间：部署探索

这份记录按技术问题而非实验编号组织。原始日志、机器结果和未采用的候选统一由[实验索引](../experiments/README.md)查找；当前稳定推理仍是 M254/M120 的 T32 Build `0x4D395832`。

## 1. 4B 模型怎样放进 KV260 的资源约束？

初始困难不仅是参数量：视觉塔、语言层、LM Head、KV 缓存和临时激活有不同的精度与访存要求。将所有组件统一压成同一低位宽会把敏感部分一起牺牲。项目按组件选择 W2/W3/W4 等存储表示，保留必要的高精度路径，冻结分片布局、偏移和哈希；板端运行时在需要时读取和暂存权重。这样的设计降低了存储压力，却不能消除权重搬运和解包成本。

曾尝试扩大语言 Prefill 的 Token 批量（T64/T128 方向），目的是让一次权重读取服务更多 Token。T64 的数值路径可以作为候选讨论，但资源、时序与完整门禁没有形成可替换的稳定整壳，因此发布版仍采用已经验证的 T32。Decode-one 实验核则试图为单 Token 避免 T32 的无效工作；一次同会话三步对照没有整体收益，容量专项也未完成，没有替换稳定核。详见[结果总表](results.md)和[原始 Decode 对照](../deployment/mage_vl4b/M325_FULL_SESSION_BOARD_RESULT.json)。

## 2. 怎样让 PS 与 PL 完成同一次多模态前向？

PS 负责视频预处理、视觉塔、Attention、Norm、激活及 KV 管理；PL 的 T32 核负责语言 Linear 和 LM Head。运行时不仅要给出正确输出，还要核对权重布局、Build ID、DMA 状态、逻辑调用和 CPU Linear fallback，避免“网页有结果”掩盖实际未走硬件的情形。[架构](architecture.md)和[源码导览](source_map.md)分别说明运行分工与历史模块依赖。

固定视频的独立安装测试确实完成了视觉前向、PL 语言计算及首 Token 回传：四帧进入接口，推理实际采用末帧两视图，159 Token、778 次逻辑调用，首 Token `230.721 s`（不含初始化）。这证明受限视频输入可以跑通，不证明四帧运动理解或秒级实时性。[公开结果摘录](../experiments/fixed_video/RESULT.json)。

在两个代表性同量化 Linear 链上，优化 A53 CPU 与 PL 成对计时分别得到约 `2.63×` 和 `2.33×` 的局部 PL 收益；完整 CPU-only 4B 运行时没有实现，因而没有整模型 CPU/FPGA 加速比。[对照方法](cpu_pl_benchmark.md)。

## 3. 哪些优化真正减少用户等待？

固定视频 `230.721 s` 首 Token 中，视觉塔约 `43.638 s`，语言 Prefill 至首 Token 约 `187.011 s`。这提示优先关注语言数据移动和调度，但不同输入画像不能直接拼成这一请求的细分账单。[耗时分析](performance_attribution_history.md)。

项目曾改进视觉 W4 解码、权重暂存与输出解析等局部路径。重要的取舍发生在输出解析：A53 短测快了约 `1.76–2.04×`，两组同输入完整视频 A/B 却没有观察到首 Token 收益，候选分别多用 `20.224 s` 和 `7.023 s`。因此稳定解析器保持不变。这个反例说明：优化一个循环，并不等于降低了用户实际等待的完整请求时间。[双顺序归档](../experiments/m332_parser_scale/REPORT.md)。

持续视频的系统问题与 4B 推理时间是两件事。环形缓冲与“忙时仅保留最新窗口”能够防止请求无限积压，却不能让分钟级语义结果变成秒级。隔离的手动 Web 入口已完成两次任务调度、真实 4B/FPGA 推理和 SSE 回传；自动报警入口的检测质量尚不足以形成同样证据。[手动复核记录](../experiments/m335_manual_web_review/REPORT.md)。

## 4. 输入设计怎样对应固定 T32 执行成本？

对固定语言链，逻辑调用数是 `154 × ceil(N/32) + 8`，其中 `N` 是视觉与文本输入 Token 总数。164 Token 落入 6 批，159 Token 落入 5 批；仅少 5 个 Token，就少一次完整批次、154 次逻辑调用。另一方面，从 159 继续压到 144 仍是 5 批，调用数不变。BACT-V2 因此关注“在任务质量约束下跨越下一条批边界”，而非追逐最大压缩率。[方法、Prompt 取舍与质量边界](bact_v2.md)。

Prompt 变短能够降低固定样例的输入长度，四个早期 GPU 回归样例保留了原判断；这不是正式监控准确率。之后的等预算改写和双时刻视图在旧样本上没有足够综合收益，保留原 P0 与视图配置。旧 12 段 AI 视频的配对复算也没有证明 BACT-159 的质量高于同为五批的 count-144。这个方法目前成立的是硬件成本阶梯和可复现选择机制，质量优势仍需要来源独立的人工标注数据。

## 当前可作出的结论

KV260 上的 4B 多模态前向与硬件成本测量已经形成实物闭环；代表性 Linear 链有局部 PL 收益，输入预算跨过 T32 边界能减少执行批次。预构建资产现已列于 Release，八分片清单也已核对；公开分片的完整下载重组仍待记录。当前固定视频仍是分钟级、只用末帧两视图，自动刀具触发缺乏可靠性验证，完整 CPU-only 对照尚未完成。项目因此更适合作为可审计的边缘多模态部署研究原型，而不是实时安全监控产品。
