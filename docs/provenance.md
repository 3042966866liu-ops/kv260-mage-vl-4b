# Provenance and rights audit

The local project snapshot contains project-specific T32/HLS, PS/PYNQ runtime, BACT research code and Web code. It also contains `ps_vision_payload/modeling_mage_vl.py`, `configuration_mage_vl.py` and model `config.json` which appear derived from Mage-VL/Transformers components. The official [Mage repository](https://github.com/microsoft/Mage) and [model card](https://huggingface.co/microsoft/Mage-VL) identify Mage-VL as Apache-2.0; the repository's root [software license](https://github.com/microsoft/Mage/blob/main/LICENSE) is MIT. Their exact upstream commit, file-level source, local modifications and notice obligations are **not established** in the local source manifests; do not represent the copied files as wholly original or assign a guessed license to them. The model identifier in board evidence is `microsoft/Mage-VL`, but identifier and model-card license do not establish that every copied file is byte-identical to a specific upstream revision.

The SSDLite checkpoint derives from torchvision model weights and is excluded from Git. The local prebuilt package also contains a hash-locked M189 ARM64 Python wheel bundle, a matching torchvision wheel and the historical M193 Pillow wheel so that first-install runtime does not depend on the owner's historical stable directory. These wheels retain their third-party licenses and are not project-original code; their exact upstream URLs, notices, and redistribution terms require package-by-package review before public upload. Quantized language shards, vision safetensors, embedding/tokenizer and bitstreams are likewise excluded from Git pending rights/asset review. The exact stable M125 language/LM Head layouts are now located and rehashed on the owner's WSL host; [the provenance audit](stable_asset_provenance.md) distinguishes asset identity from redistribution permission. `model_tools/` scripts are byte-identical copies of the workspace's historical preparation scripts; their original authorship and raw model input rights need owner confirmation.

## Owner decisions before declaring an open-source license or distributing assets

The source snapshot is already on GitHub; that fact does not itself establish a project license or third-party redistribution rights. For code the project owner actually wrote and owns, select and add one project license: MIT (short permissive notice), Apache-2.0 (permissive with explicit patent grant and notice obligations), or pause further distribution until rights are resolved. A copyleft option such as GPL-3.0 is also possible but needs a compatibility review before mixing copied code. This is a choice for the owner, not a license assignment by this audit. The owner must separately confirm authorship/coauthor permission for the T32, runtime, Web, BACT and preparation scripts, and record the exact upstream revision and modifications for the copied Mage-VL/Transformers files. None of these choices changes the licenses of Microsoft model/code, torchvision assets, AMD tools or other third-party components; their notices must remain separate. Do not upload the local prebuilt TAR until redistribution of every included model/checkpoint/bitstream asset is cleared.

Original relative paths and hashes are in [release file manifest](../manifests/release_files.json). The manifest distinguishes byte-identical snapshots from new release files; a hash is artifact identity, not license evidence. The `THIRD_PARTY_NOTICES.md` file is a disclosure of unresolved attribution, not a license grant. There is deliberately no invented MIT/Apache project `LICENSE` or `CITATION.cff`.
